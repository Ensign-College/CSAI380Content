# 7.4 Final Demonstration Video 💚

## Purpose:

Week 7 introduces almost no new technology on purpose — you finish, operate, and demonstrate what you built. In this assignment you will record a five-minute video demonstrating your project end to end: the running system, the infrastructure-as-code and GitHub pipeline that produce it, and a live troubleshooting moment that proves you can operate it, not just deploy it.

Five minutes is short. Professionals rehearse; so will you.

## Instructions:

1. **Plan your demo before recording.** Write a brief shot list covering the required segments below. Rehearse at least once — you will not fit in five minutes on the first try.

2. Record a **5-minute video** that includes all of the following:
   1. **Normal operation (≈2 minutes):** Show your architecture diagram, then demonstrate data flowing through the live system — source/application → stateful data service → ETL and/or event pipeline → Kafka → processing → downstream destination. Prove data arrives (e.g., a MySQL query showing fresh events).
   2. **Infrastructure as code (≈1 minute):** Walk through your GitHub repository — the Terraform that provisions your resources, the Kubernetes manifests and Helm values, and a green GitHub Actions run that built and deployed the system. Make the point explicitly: everything on screen is reproducible from this repository.
   3. **Troubleshooting (≈1 minute):** Break one thing on camera (stop a consumer, misconfigure a credential, or delete a pod), show how you detect it (logs, `kubectl describe`, events, lag), fix it, and verify recovery. This may be brief — the point is to show your diagnostic workflow.
   4. **Reflection (≈1 minute):** State clearly:
      1. What you did well.
      2. What you would do differently if you started over.

3. Production requirements:
   1. Your face or voice must be present — this is your demonstration, not a screen-capture slideshow.
   2. The terminal and browser text must be legible at normal playback size.
   3. Stay within 4:30–5:30. Editing is allowed; speeding up footage is allowed; cutting required segments is not.

4. Upload the video (YouTube unlisted, Google Drive, or the Canvas media tool) and add the link to your repository README.

5. **Submit** the video link and your GitHub repository link to Canvas.
