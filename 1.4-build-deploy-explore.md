# 1.4 Build, Deploy, and Explore 🟡

> **Status:** 🚧 DRAFT — not yet tested end-to-end.
> **Starter files:** [starter/terraform/](starter/terraform/), [starter/Dockerfile](starter/Dockerfile), [starter/app/server.py](starter/app/server.py), [starter/k8s/busybox-pod.yaml](starter/k8s/busybox-pod.yaml), [starter/k8s/deployment.yaml](starter/k8s/deployment.yaml), [starter/k8s/service.yaml](starter/k8s/service.yaml), [starter/.github/workflows/build-and-push.yml](starter/.github/workflows/build-and-push.yml)

## Purpose:

This assignment gives you hands-on experience taking an application from a Docker image to a working Kubernetes deployment on Google Kubernetes Engine (GKE). You will practice building, running, pushing, and pulling Docker images; creating Kubernetes deployments and services; and using commands to inspect and troubleshoot your work.

You will also establish the infrastructure-as-code (IaC) habits you will use for the rest of the course: everything you deploy is described in files, those files live in GitHub, and a GitHub Actions pipeline builds and publishes your container image automatically. Finally, you will use AI to strengthen your understanding by creating a Mermaid diagram and writing Markdown as you document what you learn.

## Instructions:

### Part One: Set Up Your Tools and Repository

1. If you haven't already, install VS Code (or Codex) and the following command-line tools:
   1. `git`
   2. `docker`
   3. `kubectl`
   4. `gcloud` (Google Cloud CLI)
   5. `terraform`

2. Use AI or a search engine to study **Agent Loops**, and how goals factor into Agent Loops.
   1. As you work through the following steps, keep two questions in mind: "What goal have I defined for my agent?" and "How will it know when it has completed the goal?"

3. Go to the Canvas assignment and accept the GitHub repository:
   1. Open the repository in VS Code or Codex. **All files you create in this exercise belong in this repository.** If it isn't in Git, it didn't happen.

4. Log in to your Vocareum-provided GCP environment and verify access to the course GKE cluster:

   ```bash
   gcloud container clusters get-credentials <cluster-name> --region <region>
   kubectl get nodes
   ```

### Part Two: Provision Your Workspace with Terraform

5. In your repository, create a `terraform/` directory. Starting from the provided [starter/terraform/main.tf](starter/terraform/main.tf) and [starter/terraform/variables.tf](starter/terraform/variables.tf), write Terraform that provisions:
   1. A Kubernetes **namespace** named with your GitHub username (this is your personal sandbox for the semester).
   2. A **Google Artifact Registry** Docker repository to hold your images.

6. Run the standard Terraform workflow and read the output of each step:

   ```bash
   terraform init
   terraform plan
   terraform apply
   ```

7. Commit the `terraform/` directory (never commit `.tfstate` files — the starter `.gitignore` handles this).

### Part Three: Deploy a Pre-Made Image

8. Deploy a pod to Kubernetes using the **busybox** image (BusyBox is a tiny Linux container image — perfect for exploring).
   1. Write a pod manifest in `k8s/busybox-pod.yaml` and apply it to your namespace.
   2. Practice the three essential inspection commands and record what each tells you:

      ```bash
      kubectl get pods -n <your-namespace>
      kubectl describe pod busybox -n <your-namespace>
      kubectl logs busybox -n <your-namespace>
      ```

### Part Four: The Docker Image Lifecycle

9. Learn how to do each of the following, and document each step with the command you used and a screenshot or terminal output in your README (start from the provided [starter/Dockerfile](starter/Dockerfile) and [starter/app/server.py](starter/app/server.py)):
   1. Pull and run a Docker image from the Docker Hub registry.
   2. Write a `Dockerfile` for a simple application (a one-line Dockerfile is a fine start).
   3. Build a Docker image from your Dockerfile.
   4. Run your local image.
   5. Push your Docker image to your Artifact Registry repository.
   6. Pull it back from the registry.
   7. Deploy your application to Kubernetes using your pushed image.
   8. **Apple Silicon (M-series) Macs:** GKE nodes are `amd64`, so build the image you push with `docker build --platform linux/amd64 ...` — otherwise your pods will crash with `exec format error`.

### Part Five: Automate the Build with GitHub Actions

10. Create a workflow at `.github/workflows/build-and-push.yml` (starting from [starter/.github/workflows/build-and-push.yml](starter/.github/workflows/build-and-push.yml)) that:
    1. Triggers on every push to `main`.
    2. Builds your Docker image.
    3. Pushes the image to your Artifact Registry repository.
    4. Use the provided GCP service-account credentials stored as a **GitHub Actions secret** — never hard-code credentials in the workflow file.

11. Push a small change and confirm the workflow runs green in the Actions tab. Include a link to a successful run in your README.

### Part Six: Deployments and Services

12. Create a **Deployment** manifest (`k8s/deployment.yaml`) that uses your Docker image from Artifact Registry, and a **Service** manifest (`k8s/service.yaml`) that exposes your deployment.
    1. Apply both, then verify with `kubectl get deployments,services,pods -n <your-namespace>`.
    2. Delete one pod and watch the Deployment replace it. Note what happened in your README.

### Part Seven: Document with AI

13. Prompt your coding agent to make a **Mermaid diagram** of how to make a peanut butter and jelly sandwich in a file called `PBJ.md`. Verify the diagram renders in your repository on GitHub.

14. Learn about Markdown using AI as your teacher. Apply what you learn: your repository `README.md` must include headings, a table of the commands you learned, at least one code block, and links to your workflow run.

15. **Submit** the link to your GitHub repository to Canvas.
